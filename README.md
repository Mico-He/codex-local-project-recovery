# Codex 本机项目恢复 · Windows

切换账号后，Codex 侧栏突然显示“没有项目”，但项目文件夹仍在？本工具尝试从本机已保存的账号配置中恢复项目清单。

## 适用版本与反馈

这是作者在 2026 年 11 月 9 日使用 Windows 桌面客户端时遇到的问题，当时安装的 Windows 应用包版本为 **26.1103.4239.0**。其他版本未验证。如果你当前版本切换账号后仍正常显示本机项目，可以忽略本工具。希望这份记录能帮助遇到相同现象的用户。

从这台电脑的配置来看，可能是客户端引入项目账号归属后，切换账号时也隔离了本机项目的显示清单。文件夹仍留在磁盘上。这个解释来自本机排查，未获官方确认。

希望官方增加一个手动选项，让用户选择哪些本机项目可以在更换账号后继续显示，同时保留各账号的聊天与云项目设置。

## 故障与排查

这次故障中，重启后侧栏仍为空，旧聊天和本地目录却还能找到。项目接口返回 0 条，本地数据库仍有 14 条登记。进一步检查桌面配置，发现旧账号的项目清单保存在非活动配置区，当前账号的清单为空。恢复需要合并清单，而不能用旧配置覆盖当前账号。

最难处理的是客户端仍在后台时会覆盖配置，原先的命令行工具因此一直等待退出。现在面板显示剩余进程，退出后自动继续。写入前备份，检查配置有无并发改动，写入后核对结果。

## 使用

需要 Windows 和 Python 3（含 Tkinter）。解压后双击 Start-Recovery.cmd，也可运行 python project_recovery_panel.pyw。

1. 保存工作，点击 **退出 Codex 进程**。按钮先请求关闭窗口，约 1.5 秒后结束仍在运行的匹配客户端进程。
2. 点击 **启动恢复**。如果还有相关进程，面板会等待退出，可点击 **取消等待**。
3. 恢复成功后，点击 **启动 Codex**。

可先用 python sync_local_projects.py 预览账号和项目数量。工具仅支持已观察到的 Windows 桌面配置结构。它合并项目名称、路径、顺序及本机项目 ID，现有聊天和云项目数据留在原配置中。它不能关闭账号隔离。新账号首次登录后需要再次恢复。原项目目录已移动时，请在客户端重新关联实际路径。

## 回滚

退出客户端，将 project-backups 中对应的 global-state-时间.json 复制回用户目录下的 .codex/.codex-global-state.json。备份可能包含本机配置信息，请留在本地。

这是独立维护的恢复工具，与 OpenAI 官方产品无关联。
